# Find papers

Use this skill to show research papers returned by selected sources. Keep each source's result order; do not judge which tool is better or save items to Zotero. The tested routes are **Codex native web search, Scite, Consensus, Semantic Scholar, Google Scholar, Google Scholar Labs, and Scopus AI**. Read [tested search routes](references/search-tools.md) for source-specific controls, metadata fields, and limits.

## Before searching

In local Codex desktop, show the bundled [search form](assets/search-form.html) in a **visible right-side Codex browser tab** before opening any search results. Use `python3` if it is available; otherwise call `load_workspace_dependencies` and use the Python executable it returns. Run that interpreter on `scripts/intake.py --output <unique temporary JSON path>` from this skill's directory; the script uses only Python's standard library and prints a one-use `http://127.0.0.1` URL. Do not require the student to install Python. If neither interpreter is available, use the chat fallback below and say the checkbox form could not run.

Open the printed URL in `@Browser` and retain the form tab binding. Get the selected in-app browser binding with `agent.browsers.get(id)` using its id from the browser inventory, set its `visibility` capability to `true`, and check that `get()` returns `true`. If it stays `false`, ask the user to show this Codex task and wait; do not ask them to fill an invisible form. After the user submits, read the JSON file and remove it, then call `await formTab.close()` on that same tab before opening any search page. Verify the form tab is gone from the browser tab list. The server exits after submission. Do not ask the user to confirm the submitted search choices or reopen the form during this search; take later corrections in chat. Prefill any topic, context, tools, tab mode, **result mode**, paper limit, or Zotero exclusion choice already supplied in the prompt using the script's matching command-line flags. The user may change those choices in the form. If all inputs were supplied and the user explicitly asks to start without the form, proceed directly.

The form requires a **topic of interest**, accepts an **optional explanation** for context and filters, has independent **checkboxes** for Codex research (native web search), Scite, Consensus, Semantic Scholar, Google Scholar, Google Scholar Labs, and Scopus AI, and lets the user choose visible or background search tabs, a maximum number of papers, and a **results view**: `compare` (default, separate lists by source) or `ranked` (one deduplicated combined list). The Zotero indicator stays neutral until the user ticks **Only show papers not in Zotero**; then it checks whether the local API can reach My Library. Do not scan My Library or request per-paper Zotero status when that box is unticked. Submission starts the search without a review step. Use the submitted values exactly, except that a later user correction overrides them. The maximum applies per source; the combined view has the same final maximum. With Zotero exclusion on, each source's target becomes greater than that maximum after exclusion. If a local form cannot be opened, ask for missing inputs in chat and clearly say that this fallback has no checkbox UI.

For **visible** mode, call `await (await browser.capabilities.get("visibility")).set(true)` for the selected in-app browser and verify `get()` returns `true`. Open every selected scholarly website and any new paper-detail or verification page with `cua.createBrowserTab("iab", url, { visible: true })`; paginate in that visible tab unless the documented Google Scholar recovery requires a new visible tab. Make sure each newly opened page appears in Codex's right-side browser preview before extracting results. Do not use `{ visible: false }` for any page in visible mode. If browser visibility stays `false` or opening the preview is queued because this task is hidden, tell the user and wait for the task to be shown; do not silently continue in background tabs. For **background** mode, use `{ visible: false }` for search and detail tabs. The intake form itself is always visible.

## Search

Make a focused question and a few keyword variants from the submitted topic and optional explanation. Extract the explanation's constraints before searching: publication dates, study types, populations or species, methods, and exclusions. Apply explicit constraints as filters before ranking and before the max-paper cutoff; use source filters to narrow discovery where available, then verify each candidate's metadata against the constraints. For example, **published after 2016** means publication year 2017 or later. If "new", a term, or an acronym has multiple plausible meanings that would materially change the search or ranking, ask one focused question in chat; do not reopen the form. If the explanation resolves it, proceed.

For selected scholarly websites, search inside Codex's built-in browser in the chosen tab mode. Use each tab's CDP Runtime.evaluate to extract **structured arrays** from rendered result cards: stable paper link or ID, title, authors, year, journal, source summary or snippet, source rank, and DOI **when the rendered card, DOI link, or title URL exposes it**. Do not treat an extracted DOI as verified unless it appears in that source UI or a linked primary record. Process roughly 3–5 cards at a time with the [candidate ledger](references/candidate-ledger.md). Do not open every paper after gathering results. If a card lacks a DOI and exclusion is off, retain it with its source link and label **DOI not shown in search result**. Only open a source detail when the user's explicit filter or the source card's missing information requires it; use a publisher page only if that source cannot resolve the needed fact. Follow **Next**, numbered page, or **Load more** until the per-source target is met or a source limit is reached. The tested Scholar page-2 recovery is in the source reference. Never inspect private site state or session tokens.

If Zotero exclusion was selected, make its snapshot before any source search. Otherwise, start the sources without contacting Zotero. Run **independent selected source searches concurrently where their tools permit**. Keep a separate tab and temporary ledger for each website. In background mode, open independent source tabs and read their rendered cards concurrently with tab-scoped calls, collecting every success or failure with `Promise.allSettled`. In visible mode, open and verify each source tab in the right-side preview in sequence, then parallelize independent tab-scoped reads; serialize foreground clicks or navigation when they compete for the shared preview. While one source waits for a page or small batch, advance another source. Do not parallelize a tool that forbids concurrent calls, including Codex's hosted web search. Keep each source's pagination, ledger count, and errors separate; one source's failure must not cancel the others.

For **Codex research**, use the available first-party web search tool iteratively: search the question, refine with terms from promising results, and screen title/snippet/DOI leads in small batches. It is a Codex web search workflow, not the separate Deep research feature in ChatGPT Work. Hosted web-search calls appear in the task transcript; the visible/background choice controls browser tabs opened to inspect a needed paper fact, not the web-search calls themselves. If web search is unavailable, mark that source unavailable and continue.

If **Consensus** blocks the selected search or needed paper details with a sign-in gate, show its sign-in flow in a **visible Codex browser tab**, even when background search was selected. Set the in-app browser's `visibility` capability to `true` and verify it; if a hidden Consensus tab triggered the gate, open the original Consensus search page with `{ visible: true }` in a new tab and follow its sign-in control. Do not copy an authentication redirect URL or switch to the user's regular browser. Ask in chat with two clear choices: **Sign in to Consensus** in that tab and tell Codex when finished, or **Skip Consensus**. Pause Consensus and leave its tab available while other independent sources continue; wait for the user's choice before resuming or skipping Consensus, and do not enter credentials or assume that waiting means skip. After the user signs in, verify that Consensus results or paper details are accessible before resuming. If background mode was selected, close the temporary visible sign-in tab and continue Consensus search in background; in visible mode, continue in the visible tab. If the user skips, close only agent-created Consensus tabs, continue with the other selected sources, and report Consensus as skipped. If it was the only source, ask for another source in chat without reopening the intake form. Do not interrupt for a sign-in button alone when the required anonymous results are accessible.

For **Google Scholar Labs**, open `https://scholar.google.com/scholar_labs/search` in Codex's browser and enter an English research question. If it redirects to Google sign-in, leave a **visible Codex preview tab** for the user to sign in or choose to skip Labs; never enter credentials or copy the authentication redirect. Continue other selected sources while waiting. After sign-in, verify that the question box or result cards are accessible and return to the selected tab mode; if the user skips or the account has no Labs access, close only agent-created Labs tabs, mark the source unavailable, and continue. Use the rendered Scholar Labs cards and **More results** button as documented in [tested search routes](references/search-tools.md). Treat its generated explanations as AI takeaways, not author abstracts. Labs and ordinary Google Scholar are separate selected sources even when they surface the same paper.

For `N = max_papers`, independently collect up to **N distinct papers matching the user's explicit topic and filters from each source**, whether or not its card shows a DOI. With **only_not_in_zotero** on, instead continue each source until it has **more than N distinct papers confirmed `not_found` in the pre-search My Library snapshot** (minimum `N + 1`); title matches without DOIs may be confirmed `in_zotero` and excluded. Do not count duplicate hits, possible Zotero matches, or papers without a verified DOI as absent. Check each small batch and its ledger count before loading more. Do not divide the target among sources or stop because another source has enough papers. If a source cannot reach its target, show its actual results and a brief access-limit reason. Use Google Scholar and Scholar Labs interactively, without bulk retrieval or a page-crawling loop.

Only when Zotero exclusion is selected: review an early title match against first author, year, and journal. The snapshot stores those Zotero fields; the ledger returns a precise reason for missing or conflicting fields. A fully corroborated title match is `in_zotero` even without a DOI. Resolve a `possible_match` from source metadata when practical; otherwise keep it out of the absent count. For other DOI-less cards that may count as absent, inspect the source's own detail UI first; use its DOI link or metadata before opening a publisher. Use Crossref title lookup only if those routes lack a DOI, with **one global sequential queue**, repeated-title cache, and a pause on HTTP 429; never fan out Crossref title queries. [Crossref documents rate and concurrency limits](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/). Compare title, year, and authors before accepting a match. Distinguish author abstracts, AI takeaways, and snippets. With exclusion off, skip this Zotero/DOI follow-up and preserve all source results that meet the topic and filters.

For `ranked` mode (the optional **Combined list** view), pool the source results, deduplicate verified DOIs and clear title/year/author matches, then show up to N papers that meet the user's stated filters. Preserve every source name for a paper. Do not invent a tool-quality judgment or open publisher pages for every row; disclose whether a short description came from an author abstract, AI takeaway, or source snippet.

For `compare` mode (the default **Results by source** view), keep each tool's own result order and use [compare_results.py](scripts/compare_results.py) on the source ledgers. Follow [compare-tools output](references/compare-tools.md): show each selected tool's returned papers separately, including repeated papers across tools. Do not add a scorecard, search-process notes, or an assessment of which tool is better.

## Optional Zotero exclusion

Only if **Only show papers not in Zotero** was selected, read Zotero **My Library** once before any source search using [zotero_check.py](scripts/zotero_check.py) with `--snapshot <unique temporary JSON path>`. This scans non-attachment items and saves a private DOI/title/metadata index. For each source's small batch, run [screen_batch.py](scripts/screen_batch.py) with the snapshot, a separate ledger, `--max-papers N`, and `--only-not-in-zotero`; see [candidate ledger](references/candidate-ledger.md). Read `count_toward_target`, `needs_doi`, and title matches needing review before continuing. Reuse the snapshot, then delete temporary batches, ledgers, and snapshot at the end. The scope is My Library, not group libraries. Do not use Zotero quick search by DOI as proof of absence.

If the selected exclusion scan fails, ask the user to make Zotero accessible or drop that filter; do not claim absence. If exclusion is **off**, never call `zotero_check.py` or create a snapshot. Run [screen_batch.py](scripts/screen_batch.py) **without `--snapshot` or `--only-not-in-zotero`** to keep source ledgers; its `unchecked` status is internal and should not appear as a per-paper claim. The form's neutral indicator makes no Zotero request while exclusion is off.

Use **three columns** in either view: **Paper**, **Source summary**, and **Source** (or **Source · Zotero** only when exclusion is on). Put the linked title, authors, and year together in Paper. Link the title to `https://doi.org/<DOI>` when that DOI was exposed in the source UI; otherwise link to the source's paper URL and mark **DOI not shown in search result**. In Source summary, relay the source's short description; label AI takeaways and snippets, and do not invent a paper finding. The third column lists the discovery source(s) and source rank. When exclusion is on, add **Not found in Zotero (My Library)** for every displayed paper; never report that status without the snapshot. Show only the result tables, plus one brief sentence if a selected source is unavailable or returns fewer than requested. Do not print query/page counts, coverage breakdowns, search notes, or a judgment about tool quality.
